# Glossary

The words this repo uses in code, docs and reviews, and what each means here. Where a term has a home in the code or another doc, it is named; that file is the authority, and this page only points at it.

**Tenancy crosses the pillars and never merges them.** A campus has all three pillars (Societies, Events, Talks), and each pillar is the same thing on every campus. Nothing in this programme turns two pillars into one, or two campuses' data into one table.

| Term | Meaning |
|---|---|
| **Campus** | One university, as a tenant. **Tenant = campus = deployment** (decision D8): each campus has its own Convex deployment, Vercel project and host, and pipeline env file (`pipeline/.env.<campus>-<env>`). Ids: `cam` (Cambridge, live) and `zz` ("Testford", synthetic, tests only). Called `campus` everywhere (`Settings.campus`, `--campus`, `CAMSOCS_CAMPUS`, `NEXT_PUBLIC_CAMPUS`, the PostHog property `campus`), never `university`, which already means something else (below). Facts shared by both languages: `webapp/lib/campus/campuses.fixtures.json`. Onboarding: `docs/campuses/README.md`. |
| **University** (the word) | Not the tenant. It already names the University events stream (`events.stream = "university"`, ENG-31), the `university` argument of `events.list`, the org level `university` (ORG_LEVELS) and `isUniversityListing` (an event the University itself lists). |
| **Pillar** | One of the three things the site is about, each with its own URL prefix, tables and pipeline stages: **Societies** (a society or club *listing*: `/societies`, the `organisations` table), **Events** (`/events`, the `events` table, the society calendar and the University stream) and **Talks** (`/talks`, the academic talks pillar, decision D7, data-model §2a). Every pipeline stage carries one pillar, or `shared` for stages that serve all three (`term_dates`, `load`, `report`). `talks_cam` (talks.cam lists a society runs) is an *Events* stage; the `talks` stage is the Talks pillar. |
| **Listing** | A society's or club's public entry: one row of `organisations` and its page under `/societies`. |
| **Source** | A public place the pipeline reads: a directory, a register, a calendar, a website, an API (`docs/source-research.md`, cited as `§N`). One source can feed several stages and source types. |
| **Source type** | The closed vocabulary `SOURCE_TYPES` (`webapp/lib/vocab.ts`, mirrored in `pipeline/.../models/vocab.py`) naming what an observation was read from (`su_directory`, `society_website`, `talks_list`…). It is also the staging directory name. Event sources (`EVENT_SOURCES`) are a separate vocabulary on events. |
| **Stage** | One step of the pipeline: a `Stage` in the ordered registry `STAGES` (`pipeline/src/camsocs_pipeline/stages/__init__.py`) with a `run(ctx)` module. Engine stages run for every campus; campus stages belong to one. |
| **Phase** | Where a stage sits in the run: seed → harvest → resolve → enrich → classify → events → inbox → load → talks → report. Harvest and events stages only write to staging; `resolve` assigns keys; `load` posts; `talks` posts the Talks pillar; `report` reads. |
| **Group** | A named set of stages run together on a schedule (`GROUPS`): `events` (daily 04:30 London), `full` (Sunday 02:00, every stage plus re-derivation) and `talks` (the Talks pillar alone). `pixi run pipeline -- sync --group <name>`; `docs/ops-vps.md` §1. |
| **Observation** | What a harvest stage saw on a page, written to staging (`var/staging/<source type>/`, `models/observation.py`) before any key is assigned. Never posted directly. |
| **Claim** | One observed value of one field of one entity, appended to `fieldClaims` by `POST /api/pipeline/claims`. The server resolves claims into the row's value and its `meta[field]` provenance (`convex/lib/resolve.ts`, data-model §1). |
| **Suppression** | An accepted removal or objection (a listing, a field, a contact address, a broker person, an event, a person's name): filtered out before posting, refused by every ingestion route and stripped from the public projection (data-model §3). Never worked around. |
| **Recorded permission** | A path a publisher gave us written permission to read whatever robots.txt says (`policy.RECORDED_PERMISSIONS`, decision D3a: the University's events API and event images). Recorded `robots_override:permission` on the `sources` row. Distinct from the D3 *society* override. |
| **NO_LLM source** | A source type whose content never reaches a model (`claims.NO_LLM_SOURCE_TYPES`, `extract.llm.NO_LLM_HOSTS`): talks.cam and the talk source types. It is parsed deterministically (source-research §6). |
| **G1** | Owner decision G1, the talks boundary: nothing read from talks.cam appears outside the `/talks` prefix, in HTML, payloads, JSON-LD, sitemaps or feeds (`webapp/lib/talks-boundary.ts`). Agents never read talks.cam-derived content. The `talks_cam` stage is labelled "talks.cam lists (G1)". |
| **Yield** | What a stage run produced: inserted + updated + unchanged rows (or staged events for an events stage). A drop against the stage's own median is the first sign a scraper broke (decision D9). |
| **Freshness** | Time since a stage's last successful run that produced something (yield above 0); `stale_after` on a group is the run-level version. |
| **`cam_only`** | The event visibility tier "own-campus members only": shown to a viewer signed in with a verified address of *this deployment's* campus (`@cam.ac.uk` on Cambridge). The stored literal stays `cam_only` on every campus, and `isCamVerified` keeps its name. `members_only` events are never shown. |
| **Deployment** | One Convex backend plus the Vercel project in front of it. One per campus (D8); dev (`hushed-rhinoceros-215`) and production are separate deployments of the Cambridge campus. |
| **Broker** | The private CRM under `/dashboard` (people, needs and offers, interactions, introductions), gated by `BROKER_EMAILS`. Per deployment, so per campus. |
